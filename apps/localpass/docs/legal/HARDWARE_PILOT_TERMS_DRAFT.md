# LocalPass Hardware Pilot Terms — DRAFT

**Working draft only. Legal review required.**

These terms are intended for pilot deployments of LocalPass Node and LocalPass Guide.

## 1. Pilot hardware models

Hardware may be provided as:

- purchased hardware;
- temporary loan;
- sponsor-funded deployment;
- earn-to-own device.

The onboarding record must state which model applies.

## 2. Loaned hardware

Unless explicitly transferred in writing, loaned hardware remains the property of the provider/sponsor.

Participants must use reasonable care and return devices at pilot end if requested.

## 3. Earn-to-own

A pilot may define transparent performance/participation milestones.

Ownership transfers only when the program confirms those milestones.

Metrics must not encourage fake scans, unsafe behavior or misleading traveler interactions.

## 4. Connectivity and maintenance

Participants should:

- keep devices charged/powered during agreed active periods;
- install reasonable firmware/security updates;
- keep venue/guide information current;
- report loss, theft or malfunction;
- avoid opening or modifying production hardware unless authorized.

## 5. No certification by hardware

Possession of LocalPass hardware does not itself grant Verified Guide, Certified Guide or Trusted Local status.

Trust status is managed separately.

## 6. Replacement and warranty

Pilot replacement policies should define:

- manufacturing defects;
- accidental damage;
- loss/theft;
- battery degradation;
- shipping responsibility;
- expected replacement time.

Commercial warranty terms must be finalized for each market.

## 7. Data generated by hardware

Devices may generate operational telemetry such as:

- health/uptime;
- firmware version;
- battery status;
- aggregate scan events;
- destination-pack version.

Do not collect precise traveler identity or location merely because the device can.

## 8. Security

Participants must not:

- clone device credentials;
- bypass revocation controls;
- distribute malicious destination packs;
- alter a device to impersonate another trusted operator.

## 9. Pilot changes

Prototype hardware may change during the pilot.

The provider may recall unsafe or compromised hardware.

## 10. End of pilot

At pilot conclusion, the operator may:

- return loaned hardware;
- purchase it if an option is offered;
- earn ownership if program requirements are met;
- migrate to a commercial plan.

Final terms must state the exact path before onboarding.
