Challenge tackled

Most travel and AI products assume stable connectivity, capable hardware, and digitally mature suppliers. In Guatapé, Colombia, that leaves two users underserved: travelers with unreliable data, and small, independently owned operators invisible to discovery that depends on global platforms, paid placement, and continuous connectivity. LocalPass separates connected preparation from offline execution: a destination pack is curated once while connected, downloaded by the traveler in one tap, and used entirely on-device from then on — with locally owned listings getting a transparent ranking boost and a visible "Support local" marker.

Tools / models used

React 19 + TS UI & state
Vite build tooling
IndexedDB offline pack store
Service worker cache-first shell + data
Rules engine (84 lines) itinerary planning — no LLM call
Bilingual JSON pack curated data, not generated

Architecture

Connected prep→ AI enrichment / curation→ Guatapé destination pack
Download once→ IndexedDB + cache-first service worker→ Local rules engine on an ordinary phone
No core action calls an API. Once the shell and pack are stored, search, planning, business discovery, essentials, language switching, and itinerary persistence all run locally.

What worked well

The offline contract held end-to-end: 100% of essential content stayed reachable after one download, with zero network calls across search, planning, discovery, and essentials. The 84-line planning engine runs in under a second and is fully auditable — no invented prices, no hallucinated listings. The browser test suite verifies COP parsing, place ranking, language switching, and cached reloads across desktop/narrow-mobile and light/dark mode.

What was challenging

Proving "true offline" without a network kill switch: the in-app Simulate offline toggle changes only capability messaging, not the real browser network, so it has to exercise the same service-worker and IndexedDB code paths a real offline device would use, not a mocked shortcut. A related first-load gap — a blank screen before IndexedDB finishes initializing — is solved with a bundled seed pack so the app is useful immediately, not just after a round trip.

How we spent our time

Early: curate and verify the Guatapé destination pack against its source boundaries. Mid-build: the deterministic planning engine, IndexedDB storage, and the cache-first service worker. Later: the bilingual UI (search, plan, directory, essentials), the browser test suite, and the simulated-offline toggle. Final stretch: documentation, the demo/tech videos, and this report.

Honest limits

Single destination, 9 demo operators. Costs, hours, and operator names require local confirmation. LocalPass is not an emergency service, a booking platform, or a certification authority. Cloud enrichment is optional and never replaces the local data contract or injects generated content into the experience.
